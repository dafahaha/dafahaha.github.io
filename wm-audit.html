wm-audit

A preregistered CPU audit suite that asks which world-model diagnostics actually predict closed-loop control.

Preregistered Reduced pilot (n=9) 66 tests Single-machine CPU

World models are trained and reported on pixel fidelity (MSE, NLL, FVD), but planners consume counterfactual action effects and reward predictions. wm-audit measures each diagnostic against the real closed-loop return and correlates them across seed and capacity, with percentile-bootstrap CIs and Holm-corrected p-values fixed before seeing data.

Problem

Perceptual fidelity numbers can look good while a planner still fails to solve the task. Without a preregistered split between "looks right" and "controls well", a model can be selected on the wrong axis.

Pilot findings (pixel_nav, 3 seeds × 3 capacities, 12k steps)

HypothesisObservedVerdict
H1: pixel composite weakly tracks return (|ρ| < 0.4) ρ = −0.317, |ρ| = 0.32 Threshold met — weak/tentative; not significant (n=9, CI crosses zero, Holm p=1.0)
H2: control composite predicts return (ρ > 0.6) ρ = 0.259 Not supported
H3: INT8 degrades calibration faster than pixel fidelity (n_pairs=9) pixel 0.433 > control 0.352 Not supported

Strongest single diagnostic: uncertainty_rho ρ = 0.70, Holm-adjusted p = 0.393 (not significant). All Holm-adjusted p-values are non-significant at n=9; these are directional signals, not confirmed effects.

Honest limits

  • Reduced pilot, not the main run. One built-in env (pixel_nav), 3 seeds × 3 capacities, 12k train steps; the locked 200k-step × 5-seed × 2-env main experiment has not been run.
  • Stand-in perceptual metrics. pixel_lpips and rollout_fvd are deterministic seeded random-conv filter banks standing in for learned VGG/AlexNet backbones; real numbers, reproducible, but not publication-grade LPIPS/FVD.
  • Underpowered. n=9 float rows; bootstrap CIs are wide and every adjusted p is non-significant. Treat findings as hypotheses for the main run, not conclusions.
  • Windows constraint. dm_control cartpole is unavailable on Windows; the pilot uses the built-in pixel_nav env only.
